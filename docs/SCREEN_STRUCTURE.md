# 화면 구조 · 지도 UX

> 화면 사이의 이동은 [USER_FLOWS](USER_FLOWS.md), 화면에 표시되는 필드의 정의는 [DATA_MODEL](DATA_MODEL.md).

## 1. 네비게이션 — 하단 탭 없음

**지도가 앱 자체다.** 지도를 상시 전체 화면으로 두고, 나머지는 시트·모달로 덮는다.

```
┌──────────────────────────┐
│ 🔍 장소 검색          (👤)│  ← 검색바 + 프로필 아이콘 (플로팅)
│                          │
│                          │
│        [ 지  도 ]        │
│     ●  ●      ●          │
│        ● (12)            │  ← 클러스터
│   ●                      │
│                          │
│                    (📍)  │  ← 내 위치
│                    ( ✚ ) │  ← 스팟 등록 FAB
└──────────────────────────┘
      [ 전체 ][ 파크 ][ 스트리트 ]   ← 필터 칩 (검색바 아래 플로팅)
```

### 왜 탭이 없나

- MVP의 사용자 행동은 **"지도 보기" 하나**다. 나머지는 거기서 파생된다
- 탭을 만들면 "저장"과 "내 정보" 탭이 대부분 비어 있다 — 빈 탭은 앱을 초라하게 만든다
- 네이버지도·구글맵도 지도가 전체 화면이다. 사용자의 기대와 일치한다
- 저장 목록·설정은 프로필 아이콘 → 시트로 충분하다

> 즐겨찾기가 실제로 쓰이고 목록 화면이 커지면 그때 탭 3개(지도/저장/내정보)를 도입한다.
> 지금 미리 만들 이유가 없다.

## 2. 화면 목록

### Must

| 화면 | 형태 | 역할 |
|---|---|---|
| **지도 홈** | 풀스크린 | 앱의 루트. 항상 아래에 깔려 있다 |
| **스팟 미리보기** | 하단 시트 (peek) | 마커 탭 시. 지도를 가리지 않고 빠른 판단 |
| **스팟 상세** | 풀 시트 / 화면 | 판단에 필요한 모든 정보 |
| **스팟 등록 — 위치 지정** | 풀스크린 지도 | 중앙 고정 핀 + 주변 기존 스팟 표시 |
| **중복 확인** | 하단 시트 | "혹시 이 스팟인가요?" |
| **스팟 등록 — 정보 입력** | 풀스크린 폼 | 필수 5개 + 접힌 선택 필드 |
| **제보** | 하단 시트 | 버튼 4개 |
| **신고** | 하단 시트 | 사유 선택 |
| **로그인** | 하단 시트 | 카카오 / Apple |
| **내 정보** | 하단 시트 | 닉네임, 내가 등록한 스팟, 설정, 로그아웃, 탈퇴 |

### Should

| 화면 | 형태 |
|---|---|
| **지명 검색** | 풀스크린 오버레이 (검색바 탭 시) |
| **저장한 스팟** | 리스트 (내 정보에서 진입) |
| **사진 추가** | 시스템 피커 + 업로드 시트 |

### 만들지 않는 화면

| 화면 | 이유 |
|---|---|
| 스플래시 | 지도를 0.2초라도 먼저 보여주는 게 낫다 |
| 온보딩 슬라이드 | 지도 앱은 열면 이해된다 |
| 회원가입 폼 | 소셜 로그인만 쓴다 |
| 프로필 페이지 (타인) | SNS가 된다 |
| 설정 화면 (독립) | 설정할 게 알림 토글 정도다. 내 정보 시트에 넣는다 |
| 어드민 화면 | Supabase 대시보드 + SQL 뷰로 대체 |

## 3. 시트 계층

전환 애니메이션으로 화면을 쌓지 않고 **지도 위에 시트를 겹친다.** 뒤로가기는 시트를 닫는다.

```
지도 홈 (항상 존재)
 └ 스팟 미리보기 시트   (peek, ~25% 높이 / 드래그업 가능)
    └ 스팟 상세 시트     (~90% 높이, 지도가 위쪽에 살짝 보임)
       ├ 제보 시트       (~40%)
       ├ 신고 시트       (~40%)
       └ 로그인 시트     (~30%)
```

등록 흐름(위치 지정 → 정보 입력)만 풀스크린 push로 처리한다. 집중이 필요한 작업이다.

## 4. 지도 UX

### 마커

| 줌 레벨 | 표시 |
|---|---|
| 넓음 (~시/구 단위) | 클러스터만. 숫자 표시 |
| 중간 (~동 단위) | 클러스터 + 개별 마커 혼합 |
| 좁음 (~블록 단위) | 개별 마커. 스팟 타입별 아이콘 |
| 선택됨 | 마커 확대 + 색상 강조 |

**아이콘은 스팟 타입(4종)으로만 구분한다.** 장애물 종류(11종)로 아이콘을 나누면
지도가 읽히지 않는다. 장애물은 상세에서 본다.

| 타입 | 아이콘 방향성 |
|---|---|
| 스케이트파크 | 램프/볼 실루엣, 채워진 마커 |
| 스트리트 | 계단·레일 실루엣 |
| 광장·공원 | 플랫 면 실루엣 |
| DIY | 거친 테두리 |

상태에 따른 변형: `caution`/`temporarily_closed`는 반투명 + 경고 점,
`no_skating`은 빗금, `removed`는 기본 숨김(필터로 켤 수 있게).

### 클러스터링

- **직접 구현한다.** 카카오 SDK에는 클러스터링이 없다.
  줌 레벨에 맞춘 지리 격자 버킷팅 + 개수 버블 (약 60줄, `spike/kakao_spike`의 `clusterize()`)
- 카메라 정지 시 클러스터를 재계산하고, **마커를 전부 지우고 다시 그리지 않고 key 기준으로 diff**한다.
  전체 재생성은 지도가 깜빡인다
- 클러스터 탭 → 해당 영역으로 확대 (스팟 목록을 띄우지 않는다. 지도 앱의 관습을 따른다)
- 완전히 같은 좌표의 스팟이 여러 개면 최대 줌에서도 겹친다 → 이건 중복 등록 신호이므로
  운영 큐로 보내는 게 맞다. UI로 해결하지 않는다

### 지도 이동 → 데이터 요청

```
지도 이동 멈춤
  → 400ms debounce
  → 이전 조회 영역 대비 이동량/줌 변화가 임계값 미만이면 skip
  → bounding box 쿼리 (limit 200)
  → 마커 diff 갱신 (전체 재생성 X)
```

로딩 중에는 기존 마커를 유지하고 상단에 얇은 프로그레스만 표시한다.
마커가 사라졌다 나타나면 지도가 깜빡이는 것처럼 느껴진다.

기술적 상세: [ARCHITECTURE](ARCHITECTURE.md#지도-데이터-조회)

## 5. 필터 — MVP는 칩 3개

```
[ 전체 ]  [ 파크 ]  [ 스트리트 ]
```

이게 전부다. 검색바 아래에 가로 칩으로 붙인다. 필터 화면·모달 없음.

### 왜 이것만인가

- 스팟이 200개일 때 난이도 필터를 걸면 결과가 3개 남는다. **필터는 데이터가 많을 때만 유용하다**
- 사용자가 실제로 가장 먼저 나누는 축이 "파크냐 스트리트냐"다. 목적 자체가 다르다
- 필터 UI가 지도 면적을 먹으면 본말전도다

### 이후 추가 순서 (스팟 밀도에 따라)

1. 난이도 (초급 — P1 페르소나 요구가 가장 강하다)
2. 야간 가능 / 조명
3. 실내외
4. 현재 이용 가능 (상태 = active)
5. 장애물 종류

**거리 필터는 만들지 않는다.** 지도의 보이는 영역이 곧 거리 필터다.

## 6. 스팟 상세 화면 구성

[USER_FLOWS F3](USER_FLOWS.md#f3-특정-스팟-정보를-확인하는-사람)의 판단 순서를 그대로 레이아웃으로 옮긴다.

```
┌──────────────────────────┐
│ ⚠ 최근 제보가 있어요 (2건) │  ← 상태 배지. 없으면 이 줄 자체가 없음
├──────────────────────────┤
│                          │
│       [ 사진 캐러셀 ]      │
│         ● ○ ○            │
├──────────────────────────┤
│ 홍대 앞 3단               │  ← 이름
│ 스트리트 · 1.2km          │  ← 타입 · 거리
├──────────────────────────┤
│ 계단 3단 · 핸드레일 · 렛지 │  ← 장애물 칩
│ 난이도 중급               │
│ 바닥: 매끈한 콘크리트 (좋음)│
├──────────────────────────┤
│ 🚨 제지 위험  보통         │  ← 킥아웃 위험도
│ 🕐 추천 시간  평일 저녁 이후│
│ 💡 조명 있음 · 야간 가능    │
│ 🏠 실외 · 무료             │
├──────────────────────────┤
│ "계단 옆 렛지가 왁싱 잘 돼  │  ← 설명
│  있음. 주말 낮엔 사람 많음" │
├──────────────────────────┤
│ 마지막 확인: 3주 전        │
│ 등록: @nickname           │
├──────────────────────────┤
│ [ 길찾기 ] [ 공유 ] [ 저장 ]│  ← 하단 고정
│ 정보 제보  ·  사진 추가     │
└──────────────────────────┘
```

**비어 있는 선택 필드는 줄 자체를 그리지 않는다.** "정보 없음"을 나열하면 스팟이 부실해 보인다.
대신 하단에 "이 스팟 정보를 보완해주세요" 한 줄을 둔다.

## 7. Empty / Error 상태

| 상황 | 화면 |
|---|---|
| 화면 내 스팟 0개 (수도권) | "이 주변엔 아직 스팟이 없어요" + [스팟 등록하기] |
| 화면 내 스팟 0개 (서비스 범위 밖) | "아직 이 지역은 준비 중이에요. 서울·수도권부터 시작합니다" |
| 네트워크 오류 | 지도 유지 + 상단 배너 "스팟을 불러오지 못했어요 · 다시 시도" |
| 위치 권한 거부 | "내 위치" 버튼 비활성 대신 탭 시 설정 이동 안내 |
| 저장한 스팟 없음 | "마음에 드는 스팟을 저장해두면 여기서 볼 수 있어요" |
| 사진 업로드 실패 | 폼 내용 유지한 채 재시도 (입력을 날리지 않는다) |
