## Phase 1 — 지도 SDK 스파이크

**이 프로젝트에서 유일하게 순서를 양보할 수 없는 단계다.**

한국 지도 SDK의 크로스플랫폼 지원은 이 프로젝트 최대 기술 리스크다.
앱 구조를 다 짜놓고 "이 플러그인으로는 커스텀 마커가 안 된다"를 발견하면 되돌리기 비싸다.

- 빈 프로젝트에 지도 하나만 띄운다. **아키텍처를 만들지 않는다**
- 더미 좌표 1000개를 마커로 뿌린다
- 클러스터링, 커스텀 마커 이미지, 중앙 고정 핀 + 카메라 이벤트를 확인한다
- iOS / Android **실기기**에서 확인한다 (에뮬레이터 성능은 의미 없다)
- 1순위(Naver)가 막히면 즉시 2순위로 같은 스파이크를 반복한다

**완료 조건**

- [x] 플러그인 의존성 resolve — Kakao `1.3.1`, Naver `1.4.4` 둘 다 충돌 없음
- [x] 스파이크 코드 정적 분석 통과 (`flutter analyze` 0 issues, 양쪽)
- [x] **Android release(AOT) + R8 빌드 성공** — APK에 `libK3fAndroid.so` (18.9MB) 링크 확인.

> `account_email` 스코프를 강제로 얹고 이 동의항목은 카카오 비즈 앱 전환

> 사용자가 본인인증을 원치 않아 **OIDC 직접 구현으로 전환**했다:
> `kakao-oidc` Edge Function(코드→토큰 교환, client_secret 서버 보관)
> + `signInWithIdToken`. 대가로 커스텀 로그인 흐름 코드가 늘었고
> 모바일 딥링크 처리(`app_links`)가 추가됐다. → ARCHITECTURE.md 갱신 필요

> **한계**: `auth.users` 행의 완전 삭제는 클라이언트 권한으로 불가능하다.
> 지금은 프로필 익명화 + 세션 종료까지고, 스토어 심사용 완전 삭제는

## Phase 6 — 상태 제보 + 운영 도구

이 단계가 이 앱을 **일반 장소 앱과 다르게** 만든다. 빼면 안 된다.

- 제보 시트 (버튼 4개)
- 신고 경로 (별도)
- `spot_reports` insert 트리거 — [상태 전이 규칙](TRUST_AND_MODERATION.md#스팟-상태-전이-규칙)
- 상태 배지 (상태 + `last_verified_at` + 열린 제보 수 파생)
- 마커 상태별 시각 구분
- 운영 SQL 뷰 3개

**완료 조건**
- [x] 코드 작성 완료 (`spot_sheet.dart` — 사진 캐러셀 실제 연동, 제보 시트 4종, 신고 시트, `flutter analyze` 0 issues)
- [x] **제보 RPC End-to-End 검증**(웹, 로그인 세션으로 앱과 동일한 `submit_report(spot_id, kind, memo)` 호출):
      `still_there` / `cant_skate` / `wrong_info` / `gone` / `inappropriate` 5종 전부 성공,
      트리거 동작이 규칙과 일치함을 확인 — `still_there`는 즉시 `resolved_at='auto_applied'` +

## 콜드 스타트 전략

**출시 시점에 수도권 스팟 150~300개가 없으면 앱의 가치는 0이다.**

이건 개발 Phase가 아니라 **Phase 1부터 병렬로 도는 별도 트랙**이다.
개발이 끝난 뒤 시작하면 출시가 몇 달 밀린다.

### 왜 이 숫자인가

수도권에서 임의로 지도를 열었을 때 화면에 스팟이 보여야 한다.
서울 주요 활동 구역(강남·홍대·여의도·잠실·성수 등) 각각에 10개 이상,
경기 주요 도시에 몇 개씩이면 150개 선에서 최소 밀도가 나온다.

### 4단계

**1단계 — 공식 시설 (쉽고 확실함)**
- 공공데이터 체육시설 목록에서 수도권 스케이트파크 추출
- 좌표·주소는 얻을 수 있지만 **사진과 실제 상태는 직접 확인해야 한다**
- 예상 30~60개

**2단계 — 운영자 직접 등록 (품질 기준선)**
- 운영자가 직접 다니며 촬영·등록
- 초기 50~80개를 운영자가 만든다. **이게 등록 품질의 표준이 된다**
- 사진 저작권 문제가 없고, 필드 작성 예시가 된다

**3단계 — 시딩 파트너 (핵심)**
- 로컬 스케이터 10~20명에게 직접 요청. 인스타 DM, 스케이트샵, 파크에서 대면
- 1인당 5~10개면 100개 이상이 모인다
- 대가: 크레딧 표기, 베타 우선 접근, **자기 동네 씬에 기여한다는 감각**
- 이 사람들이 출시 후 초기 제보자 풀이 된다

**4단계 — 기존 콘텐츠에서 추출 (보조)**
- 유튜브/인스타 스팟 영상에서 위치를 특정해 후보 목록화
- **사진은 절대 가져오지 않는다.** 좌표 후보로만 쓰고 직접 촬영
- 원작자에게 등록 제안을 겸하면 시딩 파트너 모집으로 이어진다

### 지역 전략

- **서울/수도권만 시작한다.** 전국 오픈하면 밀도가 희석되어 어디서 열어도 빈 지도가 된다
- 서비스 범위 밖에서는 "아직 이 지역은 준비 중이에요" 안내 ([Empty 상태](SCREEN_STRUCTURE.md#7-empty--error-상태))
- 범위 밖 등록도 막지는 않는다. 자발적 등록이 쌓이면 다음 확장 지역의 신호가 된다

### 하지 않는 것

- 크롤링으로 타 서비스 데이터 대량 수집 — 약관·저작권 문제
- 가짜 스팟으로 지도 채우기 — 한 번 걸리면 신뢰가 끝난다
- 광고비로 유저 모집 — 스팟이 없는 상태에서 유입시키면 전부 이탈한다. **공급이 먼저다**
