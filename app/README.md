# sk8spot — 앱 (Phase 6)

Flutter + Kakao Maps + Supabase. 스택 근거는 [ARCHITECTURE](../docs/ARCHITECTURE.md).

## 개발 루프 — 웹 빌드를 쓴다

실기기를 매번 붙이지 않는다. **웹으로 띄우면 데이터 경로·레이아웃·흐름을 전부 확인할 수 있다.**

```bash
cd app
flutter build web
node <스크래치>/serve.js        # build/web 을 localhost:8080 으로 서빙
```

브라우저에서 `http://localhost:8080`. 콘솔에 조회 로그가 찍힌다:

```
[sk8spot] bbox=fromScreenPoint spots=20 (37.4949,126.7670)~(37.6174,127.0800)
```

카카오 JS 키는 `web/index.html`에 있고, 콘솔에 `http://localhost:8080`이
**웹 플랫폼 도메인으로 등록**되어 있어야 한다.

### 웹에서 확인되는 것 / 안 되는 것

| 확인됨 | 실기기 필요 |
|---|---|
| Supabase 조회·필터·클러스터링 | 프레임 성능 |
| 마커 생성·개수·좌표 (DOM에서 검증 가능) | `applyDpScale` 실제 크기 |
| 시트 레이아웃, 상세 필드, 빈 값 처리 | 위치 권한 흐름 |
| bbox 정확도 | 길찾기 앱 연동 |

**웹 전용 함정 세 가지** (앱 버그가 아니다):
- Flutter CanvasKit이 한글 폰트를 늦게 받아 첫 프레임의 칩 텍스트가 잘려 보인다.
  리빌드되면 정상. 네이티브는 시스템 폰트라 발생하지 않는다
- 시트 위에서 휠을 굴리면 뒤의 지도(플랫폼 뷰)까지 확대/축소된다.
  DOM 요소가 휠을 직접 받기 때문이고 네이티브 뷰에는 해당하지 않는다
- 상세 시트 위에서 드래그(핸들 또는 리스트)해도 시트가 확장되지 않고 뒤의 지도가 팬(pan)된다.
  같은 이유(플랫폼 뷰가 제스처를 가로챔)로, 시트 하단의 버튼까지 스크롤이 필요한 경우
  자동화 테스트로는 도달이 안 된다 — 백엔드 호출은 인증된 `fetch()`로 직접 검증하고,
  실제 탭·드래그 확인은 실기기 몫으로 남긴다

## 실기기 실행

```bash
flutter run --release --target-platform android-arm64
```

- `--target-platform android-arm64`: 이 머신은 Smart App Control이 Enforced라
  x64용 `gen_snapshot.exe`가 시스템 정책에 차단된다. 카카오 SDK도 x86을 지원하지 않는다
- **Android 에뮬레이터 불가** — 카카오 지도 SDK는 arm만 지원한다
- 키는 `lib/env.dart`에 기본값으로 들어 있다. `--dart-define`으로 덮어쓸 수 있다

## 파일

레이어를 쌓지 않았다. 화면 2개, 쿼리 2개짜리 앱이다.

| 파일 | 역할 |
|---|---|
| `main.dart` | Supabase · Kakao SDK 초기화. 스플래시·온보딩 없음 |
| `env.dart` | 공개 키 (publishable / 네이티브 앱 키). **secret key는 두지 않는다** |
| `spot.dart` | enum·모델·레포지토리 (bbox·상세·중복 탐지·등록·사진 업로드) |
| `cluster.dart` | 격자 버킷팅 클러스터링 — 카카오 SDK에 내장이 없다 |
| `map_home.dart` | 지도 홈. bbox 조회·debounce·마커 diff·내 위치·필터 |
| `spot_sheet.dart` | 미리보기 시트 → 상세 시트 → 길찾기 |
| `auth.dart` | 카카오 OIDC 로그인, 로그인 시트, 내 정보 시트 |
| `spot_register.dart` | 등록 흐름 (위치 지정 → 중복 확인 → 정보 입력) |
| `photo.dart` | 업로드 전 사진 처리 — EXIF 방향 반영 후 재인코딩(메타데이터 제거), 리사이즈 |

`spot_sheet.dart`에 Phase 6에서 추가된 것: 사진 캐러셀(Storage 실사진 연동), 제보 시트
(아직 있어요 즉시 반영 / 없어졌어요·못 타요·정보 틀려요는 메모+사진 첨부 가능), 별도 신고 시트
(사유 칩 선택 → `inappropriate` 제보).

## 설계에서 의도적으로 한 것

**앱 시작 시 위치 권한을 요청하지 않는다.** 기본 좌표(홍대)로 지도를 먼저 띄우고,
"내 위치" 버튼을 누를 때만 요청한다. 맥락 없이 뜨는 권한 팝업은 거부당하고,
권한이 없어도 앱의 대부분이 동작한다. → [USER_FLOWS F1](../docs/USER_FLOWS.md)

**bbox는 `fromScreenPoint`로 계산한다.** Phase 1 스파이크에서 `getBounds()`가
카메라 중심을 포함하지 않는 값을 돌려줬다(약 6km 어긋남). 화면 두 모서리를
직접 역변환하는 쪽을 1순위로 쓴다. → `map_home.dart`의 `_viewportBbox()`

**마커는 전체 재생성하지 않고 key 기준으로 diff 한다.** 전체를 지우고 다시 그리면
카메라를 멈출 때마다 지도가 깜빡인다.

**조회 실패 시 기존 마커를 지우지 않는다.** 지우면 "스팟이 없는 지역"처럼 보인다.
배너만 띄우고 재시도를 준다.

**상세는 정보를 나열하지 않고 판단 순서대로 배치한다.**
지금 갈 수 있나(상태 배지) → 어떻게 생겼나(사진) → 내가 탈 수 있나(장애물·난이도·바닥)
→ 쫓겨나나(제지 위험) → 언제 갈까(조명·환경) → 어떻게 가나(길찾기).
**값이 없는 줄은 그리지 않는다** — "정보 없음"을 나열하면 스팟이 부실해 보인다.
